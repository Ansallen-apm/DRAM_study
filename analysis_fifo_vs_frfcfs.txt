Analysis of FIFO vs FR-FCFS for 4-Master Sequential Read on LPDDR4-6400 (Larger Buffer)

Configuration:
- DRAM: LPDDR4-6400 x64 (tCK = 0.3125ns)
- Masters: 4
- Traffic: Sequential Read, 1KB Burst
- Offsets: 0, 128KB, 256KB, 384KB
- Master Clock: 1000 MHz
- Request Count: 10,000 requests per master
- Max Pending Requests (per master): 32
- Controller Request Buffer Size: 64 (increased from 32)

Empirical Results (DRAMSys Simulation - Buffer 64):
- FIFO Utilization: 37.38% (Bandwidth: 19.11 GB/s)
- FR-FCFS Utilization: 69.73% (Bandwidth: 35.65 GB/s)

Comparison with Previous Run (Buffer 32):
- Buffer 32: FIFO 32.23%, FR-FCFS 50.87%
- Buffer 64: FIFO 37.38%, FR-FCFS 69.73%
- Improvement: FR-FCFS improved by ~19 percentage points (+37% relative).

Analysis:

1. FR-FCFS Performance (70%):
   - Doubling the controller's request buffer size from 32 to 64 allowed the scheduler to see a much larger window of requests.
   - With 4 masters each capable of having 32 requests pending, a shared buffer of 32 was a severe bottleneck (averaging only 8 requests per master visible).
   - With a buffer of 64, the scheduler can see ~16 requests per master on average.
   - This larger window allows the FR-FCFS algorithm to batch more requests together for the same row before switching.
   - Instead of switching after 8 requests (Row Hit Streak = 8), it can now likely switch after 16 or more.
   - Amortizing the Row Activation overhead over 16 requests essentially halves the "per-byte" overhead penalty, pushing efficiency from ~50% to ~70%.

2. FIFO Performance (37%):
   - FIFO also saw a modest improvement (from 32% to 37%).
   - While FIFO cannot reorder to fix the row conflicts, a deeper buffer allows the controller to absorb more requests from the masters.
   - This might allow for better pipelining of the command stream (e.g., issuing a Precharge for Bank 0 immediately after the last Read, while the bus is still busy with data), or simply masking some of the arbitration latency.

Conclusion:
The size of the Memory Controller's request buffer is a critical performance parameter for FR-FCFS schedulers in multi-master systems. By increasing the buffer size to 64, we unlocked the potential of the scheduler to find longer sequences of Row Hits, resulting in a dramatic increase in bandwidth utilization (reaching ~70%). This confirms that the previous configuration was bottlenecked by the shared buffer capacity.
