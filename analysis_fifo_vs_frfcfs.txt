Analysis of FIFO vs FR-FCFS for 4-Master Sequential Read on LPDDR4-6400 (Oversized Buffer)

Configuration:
- DRAM: LPDDR4-6400 x64 (tCK = 0.3125ns)
- Masters: 4
- Traffic: Sequential Read, 1KB Burst
- Offsets: 0, 128KB, 256KB, 384KB
- Master Clock: 1000 MHz
- Request Count: 10,000 requests per master
- Max Pending Requests (per master): 32
- Controller Request Buffer Size: 512 (increased from 128)

Empirical Results (DRAMSys Simulation - Buffer 512):
- FIFO Utilization: 91.39% (Bandwidth: 46.72 GB/s)
- FR-FCFS Utilization: 91.63% (Bandwidth: 46.84 GB/s)

Comparison across Buffer Sizes:
- Buffer 32: FIFO 32.2%, FR-FCFS 50.9%
- Buffer 128: FIFO 55.3%, FR-FCFS 82.1%
- Buffer 512: FIFO 91.4%, FR-FCFS 91.6%

Analysis:

1. Saturation and "Ideal" Performance:
   - With a buffer size of 512, the controller buffer is significantly larger than the maximum number of outstanding requests the masters can issue (4 * 32 = 128).
   - The system is effectively running with an "infinite" buffer relative to the offered load.
   - At this scale, both schedulers achieve near-peak bandwidth (~91%).

2. The Unexpected Improvement of FIFO (to 91%):
   - Why did FIFO improve from 55% to 91% just by increasing the buffer beyond the max pending count (128)?
   - Hypotheses:
     a) **Absence of Backpressure:** With Buffer=128 (exactly matching max pending), if the controller holds requests, the masters might stall slightly or synchronize in a way that enforces the "Round-Robin" arrival pattern (M0, M1, M2, M3...) at the arbiter input. This forces the worst-case row thrashing.
     b) **Batch Arrival:** With Buffer=512, the buffer never applies backpressure. The masters dump their requests as fast as possible (1000 MHz). If the simulation executes the masters in a way that batches their output (e.g., M0 dumps 32 reqs, then M1 dumps 32 reqs), the FIFO arbiter receives them in blocks: [M0...0, M1...1].
     - If the arbiter receives blocks, FIFO schedules blocks.
     - Block scheduling = Row Hits = High Utilization.
     - This suggests that with a non-blocking buffer, the "natural" arrival pattern from the 4 masters in the simulation environment is actually *not* perfectly interleaved, but rather somewhat batched, likely due to the absence of flow-control interactions.

3. FR-FCFS Convergence:
   - FR-FCFS also reached ~91%, which is the theoretical maximum (accounting for Refresh and unavoidable overheads).
   - At this point, the DRAM bus is fully saturated with useful data transfers.

Conclusion:
Increasing the Request Buffer Size to 512 (4x the max pending load) eliminated all flow-control backpressure. This appears to have altered the arrival pattern at the arbiter (or allowed the arbiter to accept "bursts" of requests from single masters without interruption), inadvertently optimizing the schedule even for FIFO. Both algorithms effectively achieve perfect scheduling in this unconstrained scenario.
