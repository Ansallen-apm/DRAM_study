Analysis of FIFO vs FR-FCFS for 4-Master Sequential Read on LPDDR4-6400

Configuration:
- DRAM: LPDDR4-6400 x64 (tCK = 0.3125ns)
- Masters: 4
- Traffic: Sequential Read, 1KB Burst
- Offsets: 0, 128KB, 256KB, 384KB
- Address Mapping: Adjusted to standard x64 mapping (Byte:0-2, Col:3-12, Bank:13-15, Row:16-29).
- Note: Masters are configured with `minAddress` to ensure they access distinct address ranges.
  - Master 0: Bank 0, Row 0
  - Master 1: Bank 0, Row 2 (approx)
  - Master 2: Bank 0, Row 4 (approx)
  - Master 3: Bank 0, Row 6 (approx)
  - All masters compete for Bank 0 but target different Rows.

Empirical Results (DRAMSys Simulation):
- FIFO Utilization: 32.22% (Bandwidth: 16.47 GB/s)
- FR-FCFS Utilization: 50.83% (Bandwidth: 25.98 GB/s)

Analysis:

1. FIFO Performance (32%):
   - The FIFO scheduler processes requests in arrival order.
   - The Arbiter interleaves requests from the 4 masters (M0, M1, M2, M3, ...).
   - Since all masters target the same Bank (Bank 0) but different Rows, every switch between masters causes a Row Conflict.
   - Sequence: Act B0,R0 -> Read 1KB -> Pre B0 -> Act B0,R2 -> Read 1KB -> Pre B0 ...
   - Overhead: tRP (Precharge) + tRCD (Activate) + tCAS + Burst Time.
   - With 1KB bursts (64 cycles on bus) and high overhead (~116+ cycles), the efficiency drops to ~32-35%.
   - The "thrashing" behavior is clearly observed.

2. FR-FCFS Performance (51%):
   - The FR-FCFS scheduler reorders requests to prioritize Row Hits (requests targeting the currently open row).
   - It scans the request buffer (size 32) and groups requests from the same master (since they target the same row).
   - Instead of switching after every 1KB request, it batches multiple requests (likely limited by `maxPendingReadRequests` = 8).
   - Sequence: Act B0,R0 -> Read 8KB (8x1KB) -> Pre B0 -> Act B0,R2 -> Read 8KB ...
   - By amortizing the Row Activation overhead over 8 requests instead of 1, the utilization improves significantly to ~51%.
   - Ideally, with infinite buffer depth, it could reach near 100%, but it is limited here by the number of pending requests available in the buffer to be scheduled.

Conclusion:
In a scenario with high Bank Contention (multiple masters accessing different rows of the same bank), FR-FCFS provides a substantial performance benefit (+57% throughput improvement) over FIFO by reordering requests to minimize costly Row Activate/Precharge cycles.
