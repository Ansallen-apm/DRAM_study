Analysis of FIFO vs FR-FCFS for 4-Master Sequential Read on LPDDR4-6400 (Maximum Buffer)

Configuration:
- DRAM: LPDDR4-6400 x64 (tCK = 0.3125ns)
- Masters: 4
- Traffic: Sequential Read, 1KB Burst
- Offsets: 0, 128KB, 256KB, 384KB
- Master Clock: 1000 MHz
- Request Count: 10,000 requests per master
- Max Pending Requests (per master): 32
- Controller Request Buffer Size: 128 (increased from 64)

Empirical Results (DRAMSys Simulation - Buffer 128):
- FIFO Utilization: 55.34% (Bandwidth: 28.29 GB/s)
- FR-FCFS Utilization: 82.07% (Bandwidth: 41.95 GB/s)

Comparison across Buffer Sizes:
- Buffer 32: FIFO 32.2%, FR-FCFS 50.9%
- Buffer 64: FIFO 37.4%, FR-FCFS 69.7%
- Buffer 128: FIFO 55.3%, FR-FCFS 82.1%

Analysis:

1. FR-FCFS Performance (82%):
   - With a buffer size of 128, the controller can absorb the theoretical maximum number of pending requests from the masters (4 masters * 32 pending = 128).
   - The bottleneck has completely shifted away from the controller's input capacity.
   - The scheduler now has complete visibility of all available work. It can form very long "Row Hit" sequences, essentially processing huge chunks of data for one master (one row) before switching.
   - Utilization is now likely limited only by DRAM Refresh cycles (tRFC) and the unavoidable minimum overhead of switching banks/rows occasionally. 82% is extremely high efficiency for a random-access style workload (even if sequential per master).

2. FIFO Performance (55%):
   - FIFO performance improved significantly from 37% to 55%.
   - Why? FIFO cannot reorder, so it still thrashes rows.
   - However, a very deep buffer acts as a perfect pipeline. It ensures that the memory command generator (BankMachine) never waits for a request to arrive from the arbiter.
   - It also allows the controller to issue Precharge commands for the *next* request immediately while the data bus is still busy with the *current* request's data bursts.
   - This "Hiding of Precharge/Activate" behind Data Bus utilization is maximized when there is always a deep queue of known future commands. The latency of arbitration and flow control is completely masked.

Conclusion:
Increasing the Request Buffer Size to match the total pending capacity of the system (128) maximized the performance of both schedulers.
- FR-FCFS benefited most, reaching ~82% utilization by maximizing row locality (batching).
- FIFO benefited from ideal pipelining, masking protocol latencies, reaching ~55%.
- This demonstrates that for high-performance memory subsystems, the controller's internal buffering capacity is just as critical as the scheduling algorithm itself.
