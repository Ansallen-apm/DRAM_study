Analysis of FIFO vs FR-FCFS for 4-Master Sequential Read on LPDDR4-6400 (Buffer Scaling)

Configuration:
- DRAM: LPDDR4-6400 x64 (tCK = 0.3125ns)
- Masters: 4
- Traffic: Sequential Read, 1KB Burst
- Offsets: 0, 128KB, 256KB, 384KB
- Master Clock: 1000 MHz
- Request Count: 10,000 requests per master
- Max Pending Requests (per master): 32
- Total Potential Outstanding Requests: 128

Empirical Results (Buffer Size Sweep):

1. Buffer Size = 32 (Shared Buffer Bottleneck)
   - FIFO: ~32%
   - FR-FCFS: ~51%
   - Analysis: Controller buffer forces strict interleaving and limits scheduler look-ahead. FR-FCFS provides a moderate gain.

2. Buffer Size = 64 (Intermediate)
   - FIFO: ~37%
   - FR-FCFS: ~70%
   - Analysis: Larger look-ahead allows FR-FCFS to find significant row-hit batches.

3. Buffer Size = 128 (Matches Total Pending)
   - FIFO: 55.34%
   - FR-FCFS: 82.07%
   - Analysis:
     - FIFO benefits from pipelining/hiding latencies (buffer full -> MC busy).
     - FR-FCFS achieves high efficiency by seeing all pending work.

4. Buffer Size = 256 (Oversized - 2x Pending)
   - FIFO: 90.56%
   - FR-FCFS: 90.89%
   - Analysis:
     - Critical Tipping Point for FIFO.
     - With a buffer capacity (256) significantly larger than the total load (128), the controller accepts ALL requests immediately.
     - The "natural arrival" of requests in the simulation environment (likely batched per-master due to the absence of backpressure) allows FIFO to process large sequential chunks.
     - Performance converges to the theoretical maximum (~91%).

5. Buffer Size = 512 (Oversized - 4x Pending)
   - FIFO: 91.39%
   - FR-FCFS: 91.63%
   - Analysis: Marginal gain over 256. Confirms saturation at ~91%.

Conclusion:
- **FR-FCFS** scales smoothly with buffer size (51% -> 70% -> 82% -> 91%), demonstrating its ability to optimize increasingly larger pools of random/interleaved requests.
- **FIFO** exhibits a "step function" behavior. It performs poorly (~32-55%) when the buffer size forces flow control interactions that interleave requests. However, once the buffer is large enough to absorb *all* outstanding traffic (Buffer >= 256 in this case), the lack of backpressure allows the traffic generation pattern (likely batched bursts) to dominate, resulting in near-perfect (~91%) "accidental" optimization.
